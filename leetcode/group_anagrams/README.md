两个异位词为什么必须生成完全相同的分组键？
"eat"、"tea"、"ate" 可以用什么键表示？
排序后的字符串能否作为字典键？复杂度是多少？
26位字符计数数组能否作为字典键？
为什么 Python 的 list 不能作为字典键，而 tuple 可以？
字典的 value 应保存一个单词，还是一个单词列表？

1. 字母异位词要求字母和其个数完全相同,所以他们生成的分组键是一样的
2. e->1 a->1 t->1
3. 排序后的可以直接用来做字典的键，复杂度是O(nlogn)，因为需要对字符串进行排序
4. list 不能作为字典的键，因为它是可变的,list 可变，因此不可哈希。tuple 可以，因为它是不变的,tuple 在所有元素都可哈希时可以哈希；
5. 同一个分组键可能对应多个原始单词，因此需要收集这个组里的所有成员。集合才会去重，列表会保留重复元素和原始输入

hash(key) 的作用是什么？它是否直接等于字典中的存储位置？

如果作为键的对象存入字典后又发生变化，会破坏什么关系？
tuple 是否一定可哈希？例如下面哪个可以作为键？

1. hash(key) 返回的是整数哈希值，不是字典内部数组的最终下标。字典还会根据自身容量和冲突处理规则寻找实际位置。,不等于直接的存储位置
2. 哈希冲突,两个不同的键得到相同的哈希值
3. 字典是按照哈希表实现的，理论上查找是 O(1)，但实际中可能会有哈希冲突和扩容操作,Python 字典的查找、插入和删除平均为 \(O(1)\)；严重哈希冲突时查找可能退化为 \(O(n)\)，插入还可能偶尔触发 \(O(n)\) 的扩容，但连续插入的摊还复杂度仍为 \(O(1)\)。
4. 键存入字典后，它的哈希值和相等性语义必须保持稳定。
5. tuple 只有在所有元素都可哈希时才可哈希，例如 (1, "a") 可以作为键, (1, 2, 3)可以 (1, [2, 3]) 不可以,里面有列表
