# 最终独立验收规则

版本：2026-10-24。对象：Agent Runtime Core Reference的求职导向增强。
验收由最终提交的源码与原始证据驱动，不以Codex的总结作为唯一事实。

## 一、结论分离

分别给出：
1. 工程实现：COMPLETE / PARTIAL。
2. 运行验证：PASS / FAIL / BLOCKED / NOT_RUN。
3. 就业展示证据：READY / LIMITED / NOT_READY。
4. 本人掌握：ASSESSED / NOT_ASSESSED。

Codex可以提交实现与运行结果；不能替用户证明第4项，不能替最终复核方宣布READY。低模型修复率不应被改写成高成功率；工程功能通过也不承诺录用。

## 二、先检证据完整性

| 项目 | 要求 | 不满足后果 |
|---|---|---|
| 源码版本 | 实际commit/dirty状态或明确快照hash，能对上测试运行版本 | 无法复现，不判完整通过 |
| 原始测试 | 命令/环境/退出码/JUnit或完整输出 | 仅“17 passed”摘要不足 |
| Task关联 | task/attempt/step/tool/candidate/verification准确相连 | 不能借用旧任务PASS |
| 外部效果 | 独立模拟服务request/effect各自计数 | 不用Ledger自报替代 |
| Docker | 已实际启动、终止与归属检查，不以CLI失败当清理成功 | G0/G2阻断 |
| Artifact | 数据库记录对应导出字节和SHA-256 | 不能仅给路径或空报告 |
| 真实模型 | provider/model、配置、调用与输出证据，凭据脱敏 | Fake不能顶替 |
| 评测 | 每条原始记录、分组、样本数、未完成/失败清单 | 不接受只有汇总百分比 |

## 三、八个交付门

### G0 基线与真实执行
- 复现历史17个单元测试但以本轮实际集合/计数为准。
- A/C/F的完整正常报告、步骤间恢复、真容器超时和清理。
- daemon权限/网络/超时错误不得误判容器不存在。
- 旧报告不修改，本轮Task ID与所有Artifact对应。

### G1 Manifest与独立Verdict
- 非法字段/路径/预算/镜像/测试集合拒绝。
- 原始缺陷预期失败、人工参考修复通过。
- 空测试、全skip、旧PASS、错candidate/hash/nonce、缺失/损坏报告、篡改、退出码矛盾不得PASS。
- 模型无法改变验收标准；报告不可信输入得到明确解析与交叉核验。

### G2 沙箱与候选
- 候选不改测试/配置/权限/依赖，合法路径与补丁量限制。
- 每次基准+patch新建工作区；没有宿主执行候选代码替代。
- 非root/无网络/只读根/资源限制实际可见。
- 异常清理不误杀有效Attempt或无关容器。

### G3 Context与真实模型
- RepoMap对应实际代码版本，动态未知明确标注。
- Protected Facts在裁剪与恢复中不丢失。
- 至少一个真实模型生成候选并由独立验证完成DELIVERED；失败案例保留。
- 无凭据/预算时诚实BLOCKED，不把Fake混入真实模型组。

### G4 Durable修复闭环
- Task/Candidate/Attempt/ToolCall/VerificationRun各自身份正确。
- 已提交patch恢复不重新生成候选，预算不重置。
- 结果持久后不重新执行同一已完成步骤。
- 幂等提交、认领事务、fencing、cancel、UNKNOWN和reconcile均保持。
- Runtime SUCCEEDED不直接算代码修复成功。

### G5 后端工程
- 可实际操作的CLI/API与OpenAPI。
- 输入校验、并发/连接有界、权限/配额/幂等/断流/错误契约正确。
- SQL计划与索引依据、异步阻塞/资源释放测试。
- 锁文件、迁移、静态检查、CI等价本地回归可复现。

### G6 实验与故障
- 12个固定合成case先验证，4dev/8holdout标明；gold不进入模型。
- 完整真实实验目标72任务，预算不足标INCOMPLETE；不伪造。
- 270条确定性Runtime负载与真实模型结果严格分开。
- 五类恢复及审计/Context/容器故障有重复原始结果。
- 所有关键不变量违规为0；偶发违规不能用平均通过率掩盖。
- 延迟按结果分组，小样本限制、缺测token/费用、成本预算清楚。

### G7 复现与就业证据
- 干净环境按REPRODUCE运行；无法由独立人验证的部分标SELF_REPRODUCED。
- Job要求到源码/测试/run/简历表达可一一定位。
- 有失败归因与取舍，不只展示成功。
- 不宣称生产规模、完整招聘匹配或本人已掌握。

## 四、硬性否决项

出现任一项，不得给出全套PASS：
- 用宿主脚本、Mock或静态Docker参数顶替真实沙箱。
- daemon检查异常被认为容器已终止/已清理。
- 模型自述、空测试、测试skip、伪造/陈旧PASS被当交付成功。
- 旧Attempt覆盖新状态；已提交候选身份被替换；恢复重置预算。
- UNKNOWN外部副作用无依据自动重试。
- 缺少权限/审计时仍派发被禁止副作用。
- 明文密钥、跨principal泄漏，或工具容器获得宿主控制权。
- 缺失的集成测试被跳过并计入通过。
- 人工调整黄金修复、留出集或统计分母掩盖失败。
- 复制别人的项目数字、假造commit/任务ID/原始运行数据。

## 五、独立验收方法与可执行边界

先审查源代码和证据，再在可用隔离环境中复跑安全范围内测试。上传zip不表示所有代码可在审阅环境直接执行，更不允许直接运行不可信候选代码于宿主。

审阅环境没有Docker/模型凭据时：能做静态与部分单元复核，但真实集成记录是“证据审查”，不是“本审阅方已独立重跑”。最终报告必须区分复现、日志审查与未验证。

建议最终抽查：
1. 一个旧PASS重放反例。
2. 一个Worker步骤间退出恢复。
3. 一个旧租约写回拒绝。
4. 一个实际模型修复结果。
5. 一个Docker inspect权限失败不能算清理成功的反例。
6. 一条SQL事务失败回滚。

## 六、本人能力终验（不能由Codex代答）

45分钟：8分钟系统/岗位定位；12分钟事务恢复与副作用；8分钟Verifier/沙箱威胁；7分钟Context/模型/指标；10分钟独立修改和测试。

从以下选一个尚未事先准备的变更：
- 收紧人工对账后重新排队条件并补竞态测试；
- 修改lease边界并证明等于到期时间时失效；
- 新增task_type工具权限限制并证明缓存不绕过；
- 为Verdict补充一种陈旧报告错配的拒绝断言。

不会独立解释或修改时，工程仍可作为学习参考，但不要把“独立设计并实现完整Runtime”写进本人简历。
