# 独立练习：诊断中断的提交观察日志

状态：NOT_STARTED_BY_USER，个人掌握NOT_ASSESSED。任务书与输入由Codex准备，命令实现、测试和解释应由本人完成。本目录没有预制解答，不要把已生成的项目代码当作独立贡献。

## 要解决的问题

现有examples.verify_load适合检查完整实验。实验观察进程中断时，目录可能只有SUBMISSION_INTENT或ACCEPTED，使用者仍需要定位某个提交究竟留下了哪些事实。

实现一个只读命令，例如：

```bash
python -m examples.inspect_submission <证据目录> --submission-id <ID>
```

从事件日志及可选raw文件输出结构化诊断，不查询API/数据库、不重试请求、不修改或补造证据。输入目录中的文件名应在帮助信息里说明。可先支持本练习的events.jsonl/raw.jsonl，再自行决定是否兼容load_raw_events.jsonl/load_raw.jsonl；需记录你的选择。

## 行为要求

- 只出现INTENT：不能宣称请求一定未发出或一定未受理。
- 出现ACCEPTED却没有完整观察：能定位原Task及幂等身份，但不能宣称任务仍在运行或已经成功。
- 出现FINISHED：核对对应raw、submission/task身份及状态；缺少raw或矛盾要显式指出。
- 找不到该提交：区分“这个目录没有证据”和“系统不存在这个任务”。
- 重复/冲突事件、未知事件和截断JSONL末行不能静默吞掉并报告完整。
- 跨提交的事件可以交错；不得因其他提交存在而错误判定本提交。
- 不跟随日志中任意路径读取目录外文件，不输出凭据或执行日志内容。

具体输出枚举、退出码及错误粒度由你设计。先写下契约再实现；这些选择本身是需要解释的贡献。
